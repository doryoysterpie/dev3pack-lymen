# apps/mobile/src/checkin

The app half of the check-in flow (E-05). The backend half is `POST /checkins` in `services/api/src/checkin.ts` (#45). When a scanned QR is a station QR, `App.tsx` shows `CheckinPanel` under it.

| File                | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `station-qr.ts`     | Verifies a station QR on the device with E-03's rules, in E-03's order: allowlisted signer, Ed25519 signature, the five payload fields, no more than 60 s after issue, in milliseconds, and a cut-short QR refused from its `expires_at` on. A payload that repeats a key is refused, as the backend refuses it, and a verifier that throws gives `verify_failed`, not `bad_signature`.                                                                                                                                                                                                                                                     |
| `ed25519.ts`        | The device's Ed25519, `@noble/curves` under the rules the backend applies to a wallet's signature (`walletSignatureValid`, E-05): the key and R canonical and in the prime-order subgroup, then RFC 8032's check with `zip215: false`, which itself refuses an S at or above L. It checks the station QR and the wallet's signature.                                                                                                                                                                                                                                                                                                        |
| `message.ts`        | The check-in message the wallet signs (`limen check-in v2`, five lines with no registration ID), byte for byte the text the backend rebuilds, and the registration ID check (ASCII letters, digits, `_` and `-`).                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `mwa-signer.ts`     | Mobile Wallet Adapter, in two sessions with the message on screen between them: `connect` authorizes on devnet and signs nothing; `sign` authorizes again with that account's token, has the wallet sign exactly the bytes shown, and checks the signature locally before anything is sent. Each authorization answer is checked whole (token string, accounts list, and every account address decoded to a 32-byte key) and each signed answer is checked to hold exactly one payload before any part is used. It names the account to the wallet by its key in base64, the address form MWA declares, whichever spelling the wallet gave. |
| `mwa.ts`            | Binds `mwa-signer.ts` to the real `transact` from `@solana-mobile/mobile-wallet-adapter-protocol`. Only the app imports it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `http.ts`           | The app's one HTTP function (`appFetch`), forcing `redirect: "error"` on every request so a 307 or 308 never resends a POST body to another origin.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `client.ts`         | Posts `{ qr, wallet, registration_id, signature }` through `appFetch` to `<EXPO_PUBLIC_API_URL>/checkins`, refusing any `http://` base other than `localhost`, `127.0.0.1` and `10.0.2.2` before sending a request, reads response JSON refusing repeated keys, and turns each answer into a sentence for the participant. A `201` whose `signature` is null, which the backend gives when a retry finds the pass already minted, is a check-in. A `409 pass_revoked` reads as a revoked pass.                                                                                                                                              |
| `flow.ts`           | `prepareCheckin` checks the API base URL, verifies the QR, checks the registration ID, connects the wallet and returns the message's five lines (no registration ID), account and nonce included; its `sign()` checks the QR is still in its window, has the wallet sign exactly those bytes, and posts. Nothing is signed or sent before the lines are returned, and nothing reaches the wallet until the API base URL, the QR and the registration ID pass.                                                                                                                                                                               |
| `CheckinPanel.tsx`  | The registration ID field and the Check in button; then the five lines of the message (no registration ID), with a separate Sign this message button and a Cancel; then the answer.                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `config.ts`         | Reads `EXPO_PUBLIC_API_URL` (the name the report panel uses too; must be `https://`, except `http://` on loopback and emulator hosts `localhost`, `127.0.0.1` and `10.0.2.2` for development, with any other `http://` base refused before any request) and `EXPO_PUBLIC_STATION_SIGNERS`, the allowlisted station signer IDs.                                                                                                                                                                                                                                                                                                              |
| `wallet-address.ts` | Turns an MWA account's base64 public key into its base58 address, which the backend takes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `base64.ts`         | Strict base64 and base64url, without `Buffer`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `json-keys.ts`      | Finds a key repeated in any object of JSON text and parses JSON refusing repeated keys, as the backend's copy does (`services/api/src/json-keys.ts`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

Every module but `mwa.ts` and `CheckinPanel.tsx` is pure TypeScript with no React Native imports, so `npm test --workspace @limen/mobile` runs the code the app runs. The tests drive the wallet through a fake `transact`.

## Build settings

Set both when building the app. Expo inlines them into the bundle, so neither may hold a secret.

- `EXPO_PUBLIC_API_URL`: must use `https://`, except `http://` on loopback and emulator hosts (`localhost`, `127.0.0.1`, `10.0.2.2`) for development, such as `http://10.0.2.2:8787` on the Android emulator. Any other `http://` base is refused before any request.
- `EXPO_PUBLIC_STATION_SIGNERS`, the organizer key's signer ID: the base64url of its public key, as station QRs carry it.

## What the tests check

- `station-qr.test.ts`: E-03's own fixture QRs (`fixtures/station-qr/e05-app.json`, made by E-03's `issueStationQr`) verify to the answers E-03's verifier gives:
  - a valid QR verifies to its exact payload;
  - an expired one is accepted at 60 s and refused at 60.001 s, 60.999 s and 61 s;
  - a QR cut short by its session's end is accepted 1 ms before its `expires_at` and refused at it, including one E-03 cut to 59 s because its 60 s would have ended exactly at the session's end;
  - one changed payload byte gives `bad_signature`, and no QR with one character changed, to any base64url character or a dot, at any position, is accepted;
  - the backend test's 15 QRs whose payload is re-spelled in non-canonical base64url, each signed by the organizer key, and an empty payload, are refused as `malformed` before the signature, as E-03's verifier at e1ee9b3 refuses them;
  - a key off the allowlist gives `signer_not_allowlisted`;
  - the backend test's QR whose signed payload names its session twice, matched by a pinned SHA-256, gives `invalid_payload`;
  - a verifier that throws gives `verify_failed`, which the flow reports as a QR the app could not check.
- `ed25519.test.ts`: the device refuses the 12 speccheck vectors, the eight small-order points as key or as R (noble alone accepts each as R), and a mixed-order key whose signature Node's OpenSSL accepts; on honest keys it agrees with OpenSSL on the RFC 8032 vectors, on the fixture QRs and on 200 random signatures, valid and altered.
- `mwa-signer.test.ts`: with a fake wallet that returns the message followed by its signature, as the MWA fake wallet does:
  - `connect` authorizes on devnet in one session and signs nothing;
  - `sign` authorizes again with the account's token in a second session and signs exactly the message;
  - it refuses a bad signature, a changed message, no account, or an account the wallet no longer authorizes;
  - it refuses an authorization with no token, no list of accounts, or any account address that does not decode to a 32-byte key (in both `connect` and `sign`), and a signed answer that is not exactly one payload;
  - a wallet-standard account given in base58 is asked to sign by its base64 address, as the fake wallet requires.
- `message.test.ts`, `flow.test.ts`, `client.test.ts`, `wallet-address.test.ts`, `base64.test.ts`:
  - the message bytes;
  - that `prepareCheckin` only connects the wallet and returns the five lines (no registration ID), account and nonce included, that only `sign()` has the wallet sign, exactly the bytes of those lines, and that no value passed to MWA contains the registration ID;
  - that a QR which expires while its message is shown is refused at `sign()`, before the wallet signs;
  - a backend-style signature check of the whole flow, that an `http://` API base other than `localhost`, `127.0.0.1` and `10.0.2.2` is refused before touching the wallet or sending a request, and that nothing reaches the wallet or the server early;
  - the request on the wire (including `redirect: "error"`), that `postCheckin` refuses non-loopback and non-emulator `http://` base URLs before any request, that 307 and 308 redirects fail closed with no second request through `postCheckin` and `appFetch` where plain `fetch` resends the body, that response JSON with a repeated key (plain, escaped or nested) is refused rather than collapsed, that a `201` with a null signature is a check-in, and that `409 pass_revoked` reads as a revoked pass;
  - base58 against `@solana/web3.js` values;
  - base64 against Node's `Buffer`.

`npx expo export --platform android` bundles the app with these files, which shows that their imports resolve; it does not run them.
